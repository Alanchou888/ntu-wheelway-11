# v2.2 社群路況

公開閱讀路段回報，使用 ChatGPT 登入後發布、確認、檢舉及撤回自己的內容。範圍維持總圖書館與博雅教學館周邊。

## 使用方式

1. 按主選單「社群路況」，或在路段資訊按「回報路況」。
2. 選路段、問題類型及通行影響，填寫發現時間與說明。暱稱與一張現場照片為選填。
3. 發布後，其他人可確認仍存在、已排除或現場不同，並附上補充說明。
4. 每個帳號對同一則回報只計最近一次確認。作者無法確認自己的回報，可撤回自己的內容。撤回後照片停止公開。
5. 地圖依路段合併標記回報數量。標記位置是整段參考線的中點，不表示障礙的精確位置。可從清單完成相同操作。

問題類型包含違停佔用、路面顛簸、施工封路、積水、車流較大、照明不足及其他路況。通行影響由回報者選擇，不能直接套用到每個人的能力。

## 時效與資料界線

| 類型 | 沒有新確認時的顯示期限 |
| --- | --- |
| 違停佔用 | 6 小時 |
| 車流較大 | 3 小時 |
| 積水 | 12 小時 |
| 施工封路 | 3 天 |
| 照明不足 | 7 天 |
| 路面顛簸 | 30 天 |
| 其他路況 | 1 天 |

上述為本站產品設定，逾期改顯示「待重新確認」，不宣稱已排除。新的「仍存在」確認可更新顯示時效。「有人回報已排除」及「現場有不同回報」持續保留為社群意見，不會自動成為已查核資料。

路線比較顯示相關回報數量與近期受阻提示，原本的坡度、距離排序及個人限制保留。點選社群路段不會清除個人限制或改變資料模式。沒有列入目前候選路線時，會提醒返回設定核對。

社群 API 不列入離線快取。連線失敗時保留目前頁面上次讀取的內容並顯示錯誤與更新時間，不排隊自動發布。讀取最多最近 300 則紀錄，超過時顯示範圍提示。

## 執行與儲存

- React、Vite 與 Leaflet 介面保留，新增同站 Cloudflare Worker API。
- Sites 宣告 `DB` 與 `BUCKET`，分別保存 D1 回報與 R2 照片。部署會套用 `drizzle/` 遷移。
- 公開站的資料與開發者電腦的本機資料庫分開。本機測試紀錄不會隨原始碼或網站建置上傳。
- 帳號識別由 Sites 提供的已驗證身分標頭取得，伺服器保存其 SHA-256 作為操作識別。API 不公開帳號識別或電子郵件。
- 寫入檢查來源、動作標頭、登入身分、欄位、路段、時間及每帳號頻率。照片檢查類型、檔案特徵與大小，拒絕 SVG。
- 網頁會將照片重新編碼為 JPEG，長邊最多 1600px，移除原始 EXIF。上傳檔案最多 2 MB，每則一張。重試不覆蓋已有照片。
- 回報照片不會自動作為團隊實勘照片，瀏覽器實勘草稿也不會自動上傳。

## 本機開發

使用 Node.js 24。在專案根目錄執行：

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd run db:local
npm.cmd run dev:api
```

API 與正式建置預覽在 `http://127.0.0.1:8787/`。另開終端執行 `npm.cmd run dev -- --host 127.0.0.1`，以 `http://127.0.0.1:5173/` 進行前端開發。Vite 將社群 API 轉送至本機 Worker，並提供僅限 loopback 的模擬登入。模擬登入程式不會打包進正式 Worker。

`npm run db:local` 會記錄已套用遷移的雜湊，避免重複套用。不要更改已套用的 SQL。更新結構請修改 `db/schema.ts` 並執行 `npm run db:generate` 產生下一個遷移。

`npm run preview` 啟動同一個本機 Worker，需先建置並完成本機遷移。正式建置位於 `dist/client`、`dist/server` 與 `dist/.openai`，不能只部署前端檔案來提供社群功能。

## 內容管理

公開站透過 Sites runtime secret 設定 `COMMUNITY_ADMIN_TOKEN`。開發時可放在忽略的 `.env.local`。金鑰不得放入 Git、前端程式、網址或截圖。

在網址加上 `?community-admin=1`，開啟「社群路況」後展開「內容管理」，輸入管理金鑰。可查看回報及檢舉原因，將回報隱藏或恢復公開。作者已撤回的內容不會由此恢復。

本次環境的金鑰另存於忽略的 `private/community-admin.txt`，僅供網站擁有人保管。一般使用者不需金鑰。API 也會獨立驗證管理權限，開啟管理介面網址不會取得權限。

## 驗證範圍

自動測試涵蓋匿名閱讀、登入寫入、跨帳號共享、作者權限、來源檢查、時間與欄位驗證、重複回報、唯一確認、互相衝突的意見、過期狀態、檢舉、管理隱藏與恢復、頻率限制、照片格式與大小、撤回後照片停止公開，以及超過 100 則回報時的查詢限制。

瀏覽器實際檢查紀錄與畫面保存於 `docs/evidence/v22-*`。全部本機回報明確標示為開發測試，不代表現場路況、實勘結果或真實受測者紀錄。正式 OAuth、不同真人帳號與手機拍照仍需團隊實際操作驗收。
