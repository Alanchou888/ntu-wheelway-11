# 實勘資料發布流程

維護者先檢查團隊從實勘編輯器匯出的 JSON，再決定是否更新本地公開資料。工具只處理本地檔案，不呼叫 Sites、Git 或其他遠端服務。

目前尚無團隊實勘紀錄。空白範本仍保留未知值與未查核狀態，不應填入猜測的數值、照片或日期。程式測試資料不能拿來補足實勘證據。

## 1. 準備資料

1. 團隊完成現場量測，確認兩端實際入口、各路段銜接、階梯、階差、有效路寬、最大坡度、坡道長度、路面與封閉情況。
2. 記錄實勘者、量測方式與實際查核日期，補上照片及照片說明。圖資下載日期不能代替實勘日期。
3. 在實勘編輯器匯出 JSON，另存原始照片與量測紀錄供交叉審核。
4. 指定一名團隊成員核對資料與照片。公開前先取得照片使用權，移除不必要的人臉、車牌及個人資訊。

## 2. 執行檢查

在專案資料夾執行 `npm ci`。專案使用已鎖版的 tsx 開發工具執行 TypeScript，不需要額外 API key。

```powershell
node --import tsx scripts/review-survey.ts --input "C:\資料\實勘匯出.json" --report output/survey-review.json
```

如果已安裝套件，也可以使用 `npx tsx scripts/review-survey.ts` 加上相同參數。在 Windows PowerShell 遇到執行原則限制時，使用 `npm.cmd` 或 `npx.cmd`。

預設只檢查輸入並寫入 JSON 報告，不會改動 `public/data/surveyed-routes.json`。報告檔不得放在 public 內，也不能指向輸入檔。

主控台摘要和 JSON 報告會列出：

- 每條路線及入口、路段的識別碼、缺值、查核狀態與日期。
- 封閉、階梯、路段斷點、入口與道路端點不銜接等排除原因。
- 來源及照片說明缺漏、照片格式或本地照片路徑錯誤。
- 重複的路線與路段識別碼。同一路線內的識別碼須唯一。跨路線可以共用同類型、同識別碼且內容完全一致的入口或路段，JSON 物件欄位順序不影響比較。同識別碼卻有不同證據、幾何或屬性，或入口與路段共用同識別碼，都會被擋下。原範本共用的 `survey-library` 及 `survey-boya` 可保留，並應在各條路線維持一致內容。
- 明確的 `QA_FIXTURE`、`TEST_FIXTURE`、程式測試證據或保留範例網址標記。
- 最舊的有效查核日期，以及建議複查提醒。

完整性檢查沿用網站的候選路線規則。每條路線都必須符合，任何一條不合格都會讓程式以非零狀態結束。空路線集合也不接受發布，避免意外清空原有公開路線。

照片若使用 `/photos/...` 本站路徑，先把照片放入對應的 `public/photos/...` 位置。工具會檢查檔案是否存在、是否仍在 public 內、檔頭與副檔名是否符合 JPEG、PNG 或 WebP，以及是否超過 2 MB。內嵌照片也會檢查大小與格式。這些檢查無法判斷照片是否拍到正確入口，仍需人工觀看。

HTTPS 照片不會自動連線下載。報告會標示尚未驗證遠端照片可用性，審核者須自行確認可公開讀取、照片內容與使用權。網址格式通過不代表照片已完成實勘查核。

## 3. 處理複查提醒

預設超過 30 天顯示建議複查。此天數是維護提醒，並非法律或通行標準，不會僅因查核較久就判定路線不合格。團隊可設定提醒天數：

```powershell
node --import tsx scripts/review-survey.ts --input "C:\資料\實勘匯出.json" --recheck-days 14
```

遇到施工、封閉或已知變動，應立即重新查核並更新狀態，不應只等待天數到期。

## 4. 審核後更新本地公開資料

確認全部檢查通過，且團隊已核對原始證據後，使用相同輸入加上 `--publish`：

```powershell
node --import tsx scripts/review-survey.ts --input "C:\資料\實勘匯出.json" --report output/survey-review.json --publish
```

工具會再次檢查所有資料，將原本公開 JSON 的完整內容備份到 `output/survey-backups/`，檔名包含 UTC 時間與原檔雜湊。備份成功後，透過同目錄暫存檔及重新命名更新 `public/data/surveyed-routes.json`。相同資料重跑會顯示 `unchanged`，不會重寫公開檔或新增相同備份。

如果任何檢查失敗，會顯示 `blocked`，原本公開資料仍保留。報告狀態 `published` 只表示本地檔案已更新，線上網站還需維護者執行專案既有的建置、檢查與部署流程。

先在本機切換已查核資料模式，檢查路線、反向起終點、每段照片及共享連結，再建立正式網站版本。不要將 `output`、程式測試資料或未審核草稿當作公開實勘資料上傳。

## 結束狀態與復原

- `0`：所有路線通過檢查。發布是否執行另看報告的 `publication.status`。
- `1`：資料未通過。修正報告所列問題，再次檢查。
- `2`：參數或檔案操作失敗。確認路徑、寫入權限及空間。若寫報告時失敗，請同時檢查本地公開 JSON 及備份，確認更新進度。

需要回復時，先保留目前檔案，確認備份日期與內容，再手動將選定備份複製回 `public/data/surveyed-routes.json`。此操作仍只影響本地來源，網站部署需另外執行。

報告通過表示資料符合程式規則。它無法證明量測真實、照片正確、環境持續不變，或替特定使用者保證可通行。
